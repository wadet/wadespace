## CORE GAME SPECIFICATIONS

### Universe Details
- Size: 10,000 x 10,000 AU (Astronomical Units)
- 1,000 stars (infinite energy sources, refuel at 10%/turn within 1 AU)
- 10,000 planets (0-1,000 crew recruitment, shields must be down)
- 100 black holes (instant destruction within 3 AU)
- 100 pulsars (disrupt sensors within 2 AU)
- 20 wormhole pairs (free teleportation)
- 100 starbases (50% friendly, 50% npc - repairs 25%/turn, refuel, restock torpedos)
- 1,000 asteroid fields (mining 0-1,000$ per attempt within 1 AU)
- 50 npc ships (1-3 spawn near player start, rest random across universe)
- Minimum 5 AU spacing between objects (8 AU for stars, 20 AU for black holes, etc.)

### Ship Systems

**Vital Statistics:**
- Damage: 0-100% (auto-repair 5%/turn when stationary with crew scaling, 1%/turn when moving)
- Energy: 0-100% (drained by systems)
- Shields: 0-100% (drain 2%/turn when active, absorb damage before hull)
- Crew: 0-1,000 (ship disabled at 0, affects repair rate)
- Cash: Starting $1,000-5,000 (earned from mining and destroyed npcs)
- Photon Torpedos: 0-50 max
- Reputation: 0-100 (affects npc behavior and combat outcomes)

**Weapon Systems:**
- Phasers: Instant-hit, 10 AU range, 5% damage, 50-100% accuracy based on distance, requires lock-on, 1% energy cost, 25% recharge/turn
- Photon Torpedos: 10% damage, 1 AU/turn speed, 20 AU max range, 25% miss chance, travel in straight line, 1% chance to damage warp core

**Propulsion:**
- Warp Drive: 2-9 AU/turn (0.5% energy/turn), speeds >9 cause core temp buildup
- Impulse Drive: Percentage-based 1-100% of 1 AU/turn (1% energy at 100%), cannot use with warp simultaneously
- Warp Core Temperature: 0-100%, cools 5%/turn when warp inactive, 10%/turn when impulse inactive
- Auto-Navigation: Automatically calculates heading and speed to reach target object

**Sensors:**
- 50 AU detection range
- 20 AU detailed scan range
- No energy consumption
- Disrupted by pulsars within 2 AU

### Object ID System (identifiers.py)

All objects have unique IDs with format: `<2-letter prefix><1-4 digit number>`

Prefixes:
- `st` = Star (st1 - st9999)
- `pl` = Planet (pl1 - pl9999)
- `bh` = Black Hole (bh1 - bh9999)
- `pu` = Pulsar (pu1 - pu9999)
- `wh` = Worm Hole (wh1 - wh9999)
- `sb` = Starbase (sb1 - sb9999)
- `af` = Asteroid Field (af1 - af9999)
- `s` = Ship (s1 - s9999)

The ObjectIdentifier class generates globally unique IDs and validates them.

### Command System (command_parser.py)

Natural language command parser supporting:

**Navigation:**
- `warp [2-9]` - Set warp speed
- `impulse [1-100]` or `imp [1-100]` - Set impulse speed as percentage
- `impulse on/off` - Activate/deactivate impulse
- `heading [0-359]` - Set course in degrees
- `nav [object_id]` - Auto-navigate to object (cancels on warp/impulse/heading commands)
- `stop` or `all stop` - Stop all movement and cancel auto-nav

**Combat:**
- `scan` - Scan all objects within 20 AU
- `scan [object_id]` - Scan specific object
- `lock [object_id]` - Lock phasers on target
- `fire` - Fire locked phasers
- `torpedo [object_id]` or `tor [object_id]` - Fire torpedo at target
- `targets` - Show all ships in 50 AU sensor range

**Systems:**
- `shields up/down` or `shi up/down` - Raise/lower shields
- `status` or `sta` - Display ship status
- `skip` - Skip turn

**Communication:**
- `tell [object_id] [message]` - Send message to object (for friendly starbases)
- `ask [question]` or `hal [question]` - Query LLM about game state

**Debug:**
- `debug on/off` - Toggle debug mode (shows closest 5 npc decisions)

### Enemy AI System (llm_handler.py)

Enemy ships use GPT-4o-mini for tactical decisions based on:
- Behavior trait: aggressive, neutral, or timid
- Ship condition (damage, energy, shields)
- Player reputation (0-100)
- Distance to player and other objects
- Turn count

**Behavior Traits:**
- **Aggressive:** Attack if player reputation < 70, flee only if damage > 80%
- **Neutral:** Attack if provoked or reputation < 50, flee if damage > 50%
- **Timid:** Attack only if provoked or reputation < 25, flee if damage > 30%

**Reputation System:**
- Destroying timid ships OR ships with reputation > 70: -10 reputation
- Destroying aggressive ships OR ships with reputation < 30: +10 reputation
- Reputation affects how npc ships perceive threat level

LLM returns JSON with: action, heading, speed, fire_phasers, fire_torpedos, reason

Fallback to rule-based AI if OpenAI API unavailable.

### Game Engine (game_engine.py)

Main game loop processes turns:
1. Execute player command
2. Process player auto-navigation
3. Generate and execute npc commands (using LLM)
4. Update all objects (movement, energy, damage, shields, warp core)
5. Update active projectiles (torpedos travel 1 AU/turn in straight line)
6. Check collisions and interactions:
   - Star refueling (10%/turn within 1 AU)
   - Starbase services (25% repair/turn within 1 AU, refuel, restock)
   - Planet crew recruitment (shields down, within 1 AU)
   - Asteroid mining (within 1 AU, 0-1,000$ random)
   - Black hole destruction (instant if within 3 AU)
   - Wormhole teleportation (within 1 AU, teleport to paired wormhole)
   - Pulsar sensor disruption (within 2 AU)
   - Phaser hits (instant damage)
   - Torpedo impacts (check if torpedo reached target)
7. Check game over conditions

**Game Over Conditions:**
- Player ship destroyed (damage >= 100%)
- Player ship disabled (crew <= 0)
- Player ship consumed by black hole
- Victory: All 50 npc ships destroyed

### Universe Generation (universe.py)

Uses spatial grid partitioning for efficient object placement:
- SpatialGrid class divides universe into 100 AU cells for fast proximity checks
- Objects placed with minimum distance requirements
- Stars use sector-based distribution for even spacing
- Planets orbit stars at 5-50 AU distance using proper polar coordinates
- Wormholes paired during generation
- Starbases randomly assigned friendly/npc status

### Universe Objects (universe_objects.py)

Base `UniverseObject` class with abstract methods:
- `update()` - Update object state each turn
- `get_display_symbol()` - Return ASCII/symbol for display

Concrete classes:
- **Star**: Infinite energy, symbol ★
- **Planet**: Crew available if inhabited, symbol ● (inhabited) or ○ (uninhabited)
- **BlackHole**: 3 AU destruction range, symbol ⊗
- **Pulsar**: 2 AU disruption range, pulse counter, symbol ◇
- **WormHole**: Paired teleportation, 1 AU entry range, symbol ◎
- **Starbase**: Repairs/refuel/restock, shields, damage, friendly flag, symbol ⊕
- **AsteroidField**: 5-20 asteroids in 5x5 AU cluster, symbol ✕

Position class with `distance_to()` method for Euclidean distance calculations.

## IMPLEMENTATION NOTES

### Critical Implementation Details

1. **Position and Movement:**
   - All positions use float coordinates
   - Heading is 0-359 degrees (0=North, 90=East, 180=South, 270=West)
   - Movement calculation: `x += speed * sin(heading)`, `y -= speed * cos(heading)`
   - Distance calculations use Euclidean distance formula

2. **Combat Mechanics:**
   - Phasers hit instantly if target in range and line-of-sight
   - Torpedos created as projectiles that move each turn
   - Accuracy decreases with distance
   - Shields absorb damage before hull
   - Ship destroyed at 100% damage

3. **Auto-Navigation:**
   - Calculate heading to target using `atan2(dy, dx)`
   - Set optimal speed (warp 5 if distance > 10 AU, else impulse)
   - Cancel on manual warp/impulse/heading commands
   - Stop when within 1 AU of target

4. **Energy Management:**
   - Shields: 2% per turn
   - Warp: 0.5% per turn base, increases with speed > 9
   - Impulse: 1% per turn at 100%
   - Weapons: 1% per shot
   - Auto-recharge from stars within 1 AU (10%/turn)

5. **Turn Processing Order:**
   - Player command execution
   - Auto-navigation processing
   - Enemy AI decisions (LLM calls)
   - Enemy command execution
   - Movement updates (all ships)
   - Projectile updates (torpedos)
   - System updates (energy, shields, damage, warp core)
   - Collision detection
   - Special interactions (refueling, mining, etc.)
   - Game over check

6. **Spatial Optimization:**
   - Use grid-based spatial partitioning for object queries
   - Cache nearby object lists
   - Only query necessary range for each operation

7. **LLM Integration:**
   - Log all API calls to `llm-queries.log`
   - Handle API failures gracefully with fallback AI
   - Use GPT-4o-mini for cost efficiency
   - Request JSON-formatted responses
   - Include context: ship state, npc state, nearby objects, behavior trait

8. **Error Handling:**
   - Validate all user inputs
   - Check object IDs exist before operations
   - Clamp values to valid ranges (heading 0-359, speed positive, etc.)
   - Handle missing API keys gracefully
   - Catch and log exceptions without crashing

9. **Game Balance:**
   - Enemy ships spawn with 500-2,000 cash
   - Mining yields 0-1,000$ randomly
   - Repair rates: 5%/turn stationary (crew-scaled), 1%/turn moving, 25%/turn at starbase
   - Phaser damage: 5% per hit
   - Torpedo damage: 10% per hit
   - Enemy AI makes decisions every turn

10. **UI Performance:**
    - Render only visible objects on main map (20x20 AU viewport)
    - Use minimap for strategic overview
    - Limit message history to 50 entries
    - Update display at 30 FPS
    - Cache rendered text surfaces
